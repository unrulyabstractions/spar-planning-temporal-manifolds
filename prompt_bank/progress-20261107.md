# Progress log, 2026-11-07

## prompt_bank: T0 prompt bank, checker, baseline runner, review UI (branch `prompt-bank`)

### Why
The midterm report (`midterm-report` branch, `midterm_report/latex/report.pdf`, as submitted to SPAR) is the plan
of record. Its first concrete step is the 500-prompt extraction bank plus a hand review of the prompts and of
the target models' unsteered responses, to characterize baseline behaviour. A 500-prompt seed-0 bank already
existed (Jared's `jared/spar_horizon/full_bank.py`, a copy of Alan's `alan/ptm/prompts.py`), but it does not
match the report's spec (only phrasing 0, only `a)`/`b)` labels, no unit rewrites, integer rounding that
disagrees with Table 2), Gemma 4 31B had never been run on it, and the verification grid did not exist anywhere.
Alan chose to build a fresh, self-contained subdirectory intended to become the official experiment code.

### Decisions (Alan, this session)
- Self-contained `prompt_bank/` with no imports from `alan/` or `jared/`. Rejected: importing the existing
  generator, because it would tie the official code to personal working directories and to their defaults.
- Generation covers tiers T0–T3 in design but only T0 is built; T1+ waits for the T0 gate (report A.6 step 2).
  A checker model reviews prompts at every tier with the same questionnaire.
- Exactly 471 horizon / 29 null prompts; renderings drawn at random with a configurable seed; unit-rewrite
  tolerance 2%; uniform over the 4 phrasings and 2 label styles.
- Verification grid: D from the far-delay grid, H/D log-spaced, H in the same unit as D.
- Baseline: Hugging Face `generate` (rejected vLLM: faster, but the steering phase needs the same hooks
  stack); no activation capture in the baseline (keeps it purely behavioural; capture would need a second pass).
- Review UI: annotations allowed, reviewer chosen from a drop-down, no authentication; Flask.
- Hosted models via OpenRouter, not the Anthropic SDK (Alan, mid-session: "for now let's assume OpenRouter for
  running the Anthropic/OpenAI models").

### Decisions made in implementation (not specified by the report; README "Choices made here")
1. Ties count as paying off (delay ≤ horizon), as in the existing `regime()` code. 5 extraction prompts tie at
   seed 0; flagged `horizon_equals_a_delay`. The verification grid has none by construction.
2. A unit rewrite is used only if it keeps the prompt's regime ("13 weeks" is 0.3% shorter than a 3-month delay).
3. Rewrites capped at a rendered value of 1,000 and restricted to the 7 natural units. Gives 32 of 48 grid values
   with at least one rewrite, 45 rewrites in all (no cap: 44 values, 160 rewrites, e.g. "5040 seconds").
4. Horizons balanced across the grid (each value 9 or 10 times), rather than uniform draws.
5. Null prompts are twins of horizon prompts (report: "the same prompt with the CONSTRAINT line removed");
   `ExtractionConfig(null_twins=False)` gives independent nulls.
6. Exact duplicate prompts are redrawn (see bug 2 below).
7. Verification: 100 items × 2 orders (matching `T0_PROMPTS = 200` in Augusto's budget script); ratios over
   [1/2.8, 2.8] with n even, so H/D = 1 is never on the grid (nearest 0.990, 1.010); H in years to 2 decimals;
   near delay strictly shorter than H.
8. Durations compared exactly with `fractions.Fraction` in days (1 y = 365.25 d, 1 month = 1/12 y).
9. Thinking split at the first end-of-thinking token found in the tokenizer (`</think>` Qwen, `<channel|>` Gemma 4);
   unknown families refused. Templates verified with the cached tokenizers: Gemma 4 thinking mode adds a
   `<|think|>` system turn; Qwen3.5 pre-fills `<think>\n`.

### Discrepancies found
- Report Table 2 uses two significant figures above 100 (110 s; 140, 210, 330 years); the existing generator
  rounds to integers (108 s; 139, 213, 326 years). The new code follows the report; `test_grid_matches_report_table_2`
  checks every value.
- The report's bank counts (471/29) were those of the old default-config bank, which lacks the report's template
  variation. The new bank keeps the 471/29 split; its regime mix differs: none 279 / near_only 106 / both 86 /
  no_horizon 29 (old: none 295 / near 83 / both 93 / null 29, from `PromptDefinitions/00_prompt_inventory.md`).

### Bugs found and fixed during the session
1. Duplicate prompts. Seed 0 produced identical null twins `x0063-null` and `x0351-null` (their sources differed
   only in horizon and phrasing, which the null removes; ~10% chance per seed for 29 twins over 4,200 option
   combinations). Seed 1 then produced two identical horizon prompts (`x0284` = `x0170`; ~1 seed in 7). Found by
   `test_extraction_composition` (499 distinct texts) and the seed-1 determinism test. Fix: redraw repeats in step 2,
   skip null sources whose null text exists, and `require_distinct_texts` raises on any duplicate.
   Seeds 0–19 all build.
2. Checker resume mixed settings: rerunning with different settings (e.g. thinking off) appended to the same file and
   skipped "done" prompts. Found in the smoke test. Fix: `settings` stored in `<checker>.meta.json`; a resume
   with different settings exits with the list of changed keys (verified on the smoke file).
3. `model_revision` was null: transformers 5 has no `_commit_hash` on the config. Fix: read the snapshot hash
   from the cached `config.json` path (Gemma 4 31B-it `842da379…`, Qwen3.5-27B `fc05daec…`).
4. Provenance marked every fresh build `-dirty`, because the output being written is untracked. Fix:
   `git status --untracked-files=no`.
5. Test bugs (my errors, not code): successive-ratio bound must compound the ±10% (1.254–1.874, not
   1.394–1.686); 114 minutes renders as 110 by the two-significant-figure rule; verification rounding is ≤ 0.005
   years absolute, not ≤ 0.25% relative (that bound holds only near H = D, which is where it matters).
6. Answer-parser guard: "I choose: and…" would have parsed as "a"; added a no-following-alphanumeric lookahead.

## Anthropic API as a hosted checker backend; `.env` ignored

### Why
Alan: ".env holds my Anthropic key, and I'd like to make that an option because I have a significant amount of
free credits I can use on that account." OpenRouter stays available; this adds a second hosted route.

### Changes
- Root `.gitignore` (new) and `prompt_bank/.gitignore`: `.env`. `git check-ignore -v .env` -> `.gitignore:2:.env`.
- `pbank/env.py` (new): loads `NAME=value` lines from `prompt_bank/.env`, else the repo-root `.env`; variables
  already in the environment win; values never logged. Only the variable *names* in `.env` were inspected
  (`ANTHROPIC_API_KEY`), never the value.
- `pbank/hosted_model.py`: new `AnthropicModel` (Anthropic SDK; checker spec `anthropic:<id>`, e.g.
  `anthropic:claude-haiku-5-5`). Request: `thinking={"type": "adaptive", "display": "summarized"}` (the default
  display, "omitted", returns empty thinking text), `output_config={"effort": <--reasoning-effort>, "format":
  {"type": "json_schema", "schema": CHECK_SCHEMA}}`, `max_retries=5`. A `refusal` stop reason and API
  status/connection errors are recorded as `request_error` (retried on the next run), not raised. Shared
  concurrent `generate()` moved into a small base class used by both hosted backends.
- `pbank/checker.py`: `parse_checker_spec` validates `local:` / `openrouter:` / `anthropic:`; hosted settings
  (effort, schema, no batch size) apply to both hosted backends.
- `pyproject.toml`: `hosted` extra adds `anthropic>=0.70`; resolved `anthropic==2.6.0`. SDK names verified
  against the installed package before use (`messages.create` has `thinking` and `output_config`;
  `OutputConfigParam` keys `effort`, `format`; `APIConnectionError(request: httpx2.Request)` — SDK 2.x uses
  `httpx2`, which the first version of the error test got wrong: `ModuleNotFoundError: No module named 'httpx'`).
- `tests/test_hosted.py` (new, 5 tests): `.env` parsing and precedence; checker specs; the Anthropic request
  fields and reply mapping; refusal and connection error recorded; `anthropic:` treated as hosted.
