## Appended: Guttman-effect check on the centroid parabola (`scripts/guttman_check.py`)

Motivated by Shantanu's Slack note (2026-09-25): an arch in PC1–PC2 of ordinal data is the generic Guttman
(horseshoe) signature of similarity decaying with ordinal distance, and would make "PC2 quadratic with a vertex
near 1 year" a range artefact. Tests fixed before running: (a) polynomial ladder (PC_k ~ degree-k polynomial
of log H), (b) banded similarity (centroid distance as a function of |Δ log H|), (c) vertex-tracks-midpoint
(parabola refit on sliding 9-bin windows; slope of vertex on window midpoint), (d) PC2 vs split-half noise,
(e) matched banded null (exp(−|Δt|/ℓ) GP centroids with fitted ℓ and noise; 200 draws).

Reading:
1. The vertex is a range artefact: it tracks the window midpoint with slope ≈ 1 (0.98–1.16), exactly as the
   banded null predicts (1.01–1.05), and the full-range vertex (0.6–1.1 y) sits at the grid midpoint (0.81 y).

2. The arch is the Guttman signature: centroid distance is a function of |Δ log H| alone at R² 0.72–0.88 with

3. What survives beyond Guttman: the observed centroid set is MORE planar than a generic banded process —

   vs 0.58–0.78 expected). So the response to log H is close to a two-function family (linear + quadratic)
   rather than the full polynomial ladder of a smooth banded process; that is a statement about the
   representation, not an artefact. A single-direction affine model is still rejected (PC2 signal ≫ noise).
4. Consequence for the hypotheses: H2 becomes "the horizon response occupies ≈ 2 dimensions with a
   Guttman-type arch whose curvature location is not a landmark"; report ℓ (the decay length of similarity
   in decades) instead of a vertex.

## Appended: LEACE erasure check on the matrix run (`ptm/erasure.py`, `scripts/leace_check.py`, `tests/test_erasure.py`)

Question: on the mixed population (3 renderings × 2 domains × 30 configs) pooled per-cell PCA never shows
horizon (|rho(PC1)| 0.05–0.27). Is that only a variance budget, i.e. does the horizon geometry appear in
unsupervised PCA once the nuisance concepts are linearly erased?

Method. LEACE (Belrose et al. 2023) closed form, own implementation in the principal basis of the fitted
rows (`ptm/erasure.py`; `OrthogonalErasure` = our earlier nuisance-subspace projection for comparison).
Erasure fitted on the 1440 train-split main rows and applied to the 432 test-split rows (6 unseen
configs); PCA on the erased test rows. Blocks: rendering (3), domain (2), rendering×domain cell (6),
scenario parameters (5 continuous); config (6) and prompt identity (config×cell, 36) erased in-sample on
the test rows (balanced with horizon by design → a centring within level). Tests (5): zero cross-covariance
and equal class means after erasure (1e-13), idempotence, rank k−1, MSE change smaller than the orthogonal
projection (0.958 ratio on an anisotropic synthetic), held-out class accuracy 1.00→0.34 with ridge R² for the
graded signal 0.994→0.993, continuous-concept R² exactly 0.

## Appended: PLS2 / reduced-rank ridge polynomial ladder (`ptm/pls.py`, `scripts/pls_check.py`, `tests/test_pls.py`)

Shantanu's suggestion was a two-block PLS (PLS2) between activations and a multi-column target. Implemented
with the target block = Legendre polynomials of log10 H (degree 1..4, orthogonalised in degree order on the
training rows). Synthetic tests showed the known PLS2 failure mode: its components are ordered by raw
covariance, so when nuisance variance dominates (class offsets ≫ signal; the residual stream) sampling noise
in the cross-covariance pulls the components toward nuisance directions and PLS2 spends components deflating
nuisance (degree assignment 1,1,1,1). Added reduced-rank ridge regression (RRR: full dual-form ridge predictor
of the block, truncated to rank k by SVD of the fitted values) with the same interface; it is exact in that
regime. Both report held-out R² per degree vs k, the share of held-out activation variance and of
between-horizon centroid variance along each response direction (regression of X on the kept target
combinations, orthonormalised in component order), and the degree each component tracks.
```

.venv/bin/python scripts/pls_check.py runs/qwen3-14b_matrix_s0 figures/qwen3-14b_matrix_s0/pls   (log: figures/.../pls_check.log)
```
