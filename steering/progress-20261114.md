## Step 2: which prompts a fit uses: `--include-none`, the verification guard, `--exclude-horizons`

### Summary

- `--regimes` is replaced by one switch, `--include-none / --no-include-none`. The default is **on**, per the written
  spec: the report's Methods say "none" prompts are "used for extraction". It applies to everything fitted: CAA,
  reward and choice directions, and the curve. Alan chose a single switch so the controls are always fitted on the
  same prompts as CAA.
- `steer.fitting.select` now always leaves out verification-grid prompts, and `fit.json` gains `excluded`, a count per
  reason: `not_extraction_split`, `no_horizon`, `none_regime`, `excluded_horizon`.
- `--exclude-horizons H ...` (grid values such as "3 years") holds horizons out for calibration. A value that is not a
  stated horizon of the bank is refused, so a typo can't silently exclude nothing.
- The README's choice 1 now records what leaving "none" out costs on t0_s0:
  - the curve starts at 10 days instead of 30 s, and the next ten horizons rest on 1–9 prompts each;
  - CAA's short class drops from 350 to 71 prompts;
  - cos(CAA, choice) on the Qwen3.5-2B smoke run rises from 0.862 to 0.904.

### Decisions

- **Verification prompts are filtered out, not refused (a change from the draft reply to Augusto).** The draft said
  fit.py would refuse verification-grid prompts. But `extract.py --split all` and `--split verification` are
  legitimate: the evaluation team may want those activations for its own nulls. Refusing would block such a directory
  from ever being fitted. Filtering, with the count recorded, keeps the guarantee without depending on a default.
- **The `regimes` setting is gone from `FitSettings`, not kept alongside the switch.** Two ways to say the same thing
  would let them disagree. `fit_regimes(include_none)` derives the tuple.

## Fix: steering outputs could claim a clean commit with uncommitted steering code

### Bug

- **Root cause.** `extract.py` and `fit.py` recorded `code_commit` with pbank's `git_commit()`. Its dirty check runs
  `git status -- .` with `cwd=prompt_bank/`, so it only ever looked at prompt_bank/.
- **Effect.** An `extract.json` or `fit.json` written with uncommitted changes to steering/ recorded a clean hash.
  That breaks Augusto's versioning point (§4.1 item 7): a report card could cite a commit that didn't produce the
  method.
- **How found.** While planning the step 3 search log, which records the commit of every fit. I read
  `git_commit()`'s source, then demonstrated it by appending a comment to a steering file and calling it:

  ```

  ```

- **No published output is affected.** No steering output has been shared; the smoke fits live in the scratchpad.

### Fix

- `git_commit(*code_dirs)` checks the given directories. The default is prompt_bank/, so pbank's own outputs (banks,
  checks, baseline runs) behave as before.
- New `steer.provenance.code_commit()` checks steering/ and prompt_bank/, since steering results depend on both: steer
  imports pbank's parser and model runner. `extract.py` and `fit.py` use it.
- Committed on its own (the commit titled 'recorded code_commit is "-dirty" ...'), because it changes recorded
  behaviour.

## Step 3: records of what was fitted (`fit_uids.jsonl`) and of what was tried (`search.jsonl`)

### Summary

- **`fit_uids.jsonl`** is written next to every fit (Augusto's item I3). It has one row per fitted prompt:
  - the activation row and uid;
  - regime, stated horizon and its grid value, H/D, reward multiplier;
  - option order, label style (`a)/b)` or `1)/2)`) and the far option's label;
  - the baseline's chosen option and label;
  - its CAA class (`long`/`short`/null), its reward class (`high`/`low`/null), and its held-out fold.

  The order and label fields are what his check C1 (letter balance within each CAA class) needs, without re-joining
  the bank.
- **`fits/<activations>/search.jsonl`** (item I8). `fit.py` appends one line on every run, whatever the outcome
  (`written`, `refused`, `error`), with:
  - time and code commit;
  - activations and bank;
  - all settings;
  - for written fits, the output path, prompt count, the per-reason exclusion counts, and the headline diagnostics.
- `steer.fitting.FitResult` gains `caa_class`, `reward_class` and `fold` per row. They were already computed inside the
  fit; they just weren't returned.
- `fit.py:main` is now parse, then `run()` wrapped in the search-log writer.

### Decisions

- **The search log is written by `fit.py` itself, append-only, including refusals and errors.** A hand-kept list of
  what was tried gets skipped exactly when it matters. Logging only successful fits would hide runs that were attempted
  and then redone under another name.
- **Headline diagnostics go in the log row**, so that choosing among fits by their diagnostics is visible in the log
  itself, not only in fit.json files that might later be deleted.

## Step 4: the edits inside the model (torch edits, the generation hook, replay) and a per-model gate

### Summary

Augusto's item I1, and the generation-time hook we agreed to build.

- **`steer/edits.py`.**
  - `LinearEdit(direction, typical_norm)` is kind "push": x is a strength, a fraction of the typical norm.
  - `CurveEdit(manifold, mode)` is kind "target": x is a shift in decades; modes `snap` and `displace`.
  - Both expose `delta(h, x, ctx)`, a displacement at every position, with x a number or one value per row.
  - `EditContext` carries per-token role (pad / prompt / generated), absolute position, the mask, and per-row facts.
    Included now so the signature never has to change: centroid substitution needs each prompt's stated horizon.
- **`steer/hooks.py`.**
  - `steering(model, edit, x, layer, positions, rows, prompt_len, record)` is a context manager.
  - `positions` is `all`, `prompt`, `generated` or a callable; padding is never edited.
  - Roles come from a forward pre-hook that reads `cache_position` and `attention_mask` on every pass. The pass
    starting at position 0 is the prompt; later passes are generated tokens.
  - `record` collects each pass's context and the per-token norm of the displacement, so random controls can be
    matched to the edit's size token by token.
  - `replay_logits(...)` is one teacher-forced pass with the edit: the replay readout Augusto plans for screening.
- **`tools/check_hook.py`**, a gate per model: exact zero edit, correct roles, a strong edit has an effect.

### Decisions

- **Edits return displacements and the hook masks them.**
  - Keeps edits position-agnostic.
  - Gives the size profile for matched nulls directly.
  - Unedited positions keep their original bf16 bits, via `torch.where`, rather than going through a cast round trip.
- **Arithmetic in float32 (configurable), cast back to the model dtype once.** float64 parity with numpy is the test;
  float32 is what runs on the GPU.
- **`displace` computes c(t-hat + x) − c(t-hat) with the same interpolation for both terms.** At x = 0 the displacement
  is then exactly zero, so the zero-edit null (N0) is bit-exact for the curve too, not just close.
- **Roles are read from the forward call's own arguments, not tracked by counting calls.**
  - A counter would break if generate() were called twice inside one context, or if a pass were skipped.
  - `cache_position` gives absolute positions directly; when it's absent, they're inferred from the attention mask's
    length.
- **The per-model gate is a script, not only a test.** The tests can't run Gemma 4 31B here. Whether `generate()`
  passes `cache_position` and `attention_mask` the same way depends on the model class and the transformers version.
  `check_hook.py` exits 1 if anything is off, so it can block the first steered Gemma run instead of being remembered.

## Step 5: method bundles (`bundle.py`, `steer/methods.py`) and `check_hook.py --method`

### Summary

Augusto's hand-over format, his §4.1 item 1.

- **`bundle.py --fit <fit dir> --activations <extract dir>`** writes
  `methods/<model>/<method>__<activations>__<fit name>__L<layer>_<site>/`, one bundle per method:
  - `caa`, `curve-snap` and `curve-displace` (the methods);
  - `reward` and `choice` (concept controls by the same recipe; Augusto's N5 lists both).
- **Each bundle** holds:
  - `method.json`: format `steer-method/1`; the kind (push or target) and edit class; the layer and its convention,
    the site and the default positions (`all`, per the report); the request x with name, unit and sign; what it was
    fitted on (model and revision, run, bank and activations hashes, settings, include-none, exclusions); training
    (closed form, `selected_by_search: false`, a pointer to the search log); the three code commits (extract, fit,
    bundle); and the SHA-256 of every other file;
  - `arrays.npz`;
  - copies of `fit.json`, `fit_uids.jsonl` and the activations' `search.jsonl`.
- **`steer.methods.load(path)`** checks every hash and returns a `Method` with `.edit`, `.layer`, `.site`,
  `.positions`, `.kind`, `.structure` (direction and typical norm, or the `Manifold`) and `.fit_uids()`.
- **`Method.refit(activations, bank, uids=, horizons=)`** (item I4) reruns the fit with the bundle's settings.
  - `horizons` relabels prompts, e.g. a within-stratum shuffle for the label-shuffled null N4.
  - It refuses verification-grid and no-horizon uids, and activations or a bank other than those fitted on.
- **`tools/check_hook.py --method <bundle>`** takes the model and layer from the bundle and adds two things:
  - check 3 runs the method itself at `--strong`;
  - check 4 runs the method at x = 0, which must be exact except for `curve-snap`, where it is reported.
- `methods/` is git-ignored.

### Decisions

- **One directory per method, rather than one per fit with several methods inside.** Augusto's report card refers to
  "one exact method". Separate bundles let each carry its own hash set and be handed over or published alone.
- **Concept controls are bundled as methods.** They are applied exactly like CAA, so the evaluation pipeline needs no
  special case for them.
- **Random controls are not bundled.** Shared random draws per (model, layer, site) are an open §4.1 point (item 6),
  waiting for Augusto's answer on families and K.
- **`relabel` uses the bank's own H/D rule** (stated horizon days / far delay days, `pbank/t0.py:make_record`).
  Checked against every prompt, and so as a test: relabelling to the record's own stated horizon reproduces all 671
  stored values exactly. Relabelling to the grid value would have mismatched 53 rewritten prompts, e.g. x0026
  "122 days" vs "4 months".
- **The fixture's extract.json now has the same top-level fields as a real one.** bundle.py first failed on it with
  `KeyError: 'model'`. The fixture was incomplete; bundle.py was not changed to tolerate missing fields.

## Step 6: upload scripts for Hugging Face and GCS (hosting not decided yet)

### Summary

- `tools/upload_common.py` collects files and names them by their path relative to the repository root.
- `tools/upload_hf.py` publishes to a dataset repo with `huggingface_hub`.
- `tools/upload_gcs.py` publishes to `BUCKET/PREFIX` with rclone.
- Both are dry runs unless given `--upload`. They upload `SHA256SUMS` alongside the files, refuse a destination that
  already has files, refuse credential-looking files, `.git` contents and symlinks, and verify after uploading.

### Decisions

- **Follow the team's existing practice instead of adding dependencies.** Augusto's GCS uploads use rclone with a
  service-account key file, plus `rclone check` and a file count (`phrasing_study/scripts/run_pipeline.sh`). His
  Hugging Face uploads use `huggingface_hub`, with new repos private (`multiturn_planning/scripts/upload_hf.py`). Both
  tools were already installed here, so `google-cloud-storage` was not added.
- **No overwriting, unlike Augusto's idempotent HF script, which skips files that already match.** A method bundle that
  could be replaced in place under the same name would break "a report card refers to one exact method". An
  interrupted upload is redone under a new `--prefix` instead.
- **Names mirror the repository**, so `steer.methods.load` and `activations.load` work on a download at a checkout's
  root without path changes.
- **A failed initial GCS listing aborts.** The first draft treated any `rclone lsf` failure as "the destination is
  empty", so an authentication error would have gone on to the copy. Now only "directory not found" counts as empty.
