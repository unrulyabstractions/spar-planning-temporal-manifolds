# Progress 2026-11-10: steering-vector package, first version

Branch `steering-vectors` (from `prompt-bank` at 86b1db5).

## Summary

Alan's assignment from the last team meeting is prompt generation plus steering-vector computation for a
user-chosen model. He asked to keep the two separate so each is easier to validate. This entry covers the first
draft of the steering-vector side: a new `steering/` package. It computes the report's (Appendix A.3) linear
direction (CAA), the manifold curve, and the controls, all from a prompt bank plus an unsteered baseline run.

Pipeline:

1. `prompt_bank/baseline.py` generates. It now also stores each reply's exact generated token ids.
2. `steering/extract.py` replays those ids as one teacher-forced forward pass per prompt. It keeps the residual
   stream at the answer-label token and the token before it, at the requested layers.
3. `steering/fit.py` writes, on the CPU:
   - CAA, the reward-contrast control, random controls, and a "choice" direction (diagnostic only);
   - the manifold curve;
   - diagnostics.

## Decisions (and alternatives rejected)

- **Steering is a separate package that imports pbank instead of copying from it.** Alan asked for the
  separation. Copying the parser, regime facts and chat-template handling would let the two drift apart. The
  steering code reads prompt records but never builds or changes them.
- **Activations are read by replaying the baseline's token ids, not by generating again inside extraction.**
  - Rejected option 1: re-tokenizing the baseline's decoded text. It is not guaranteed to reproduce the ids.
  - Rejected option 2: generating again inside extract.py. That spends a second generation's GPU time, and the
    activations could then belong to replies other than the ones reviewed.
  - Gains: extraction is minutes rather than hours, and other layers can be extracted later without
    regenerating.
  - Batch 1, so there's no padding.
- **Layer convention: layer L = `hidden_states[L]` = the output of block L-1 (0-based).** This matches Jared's
  convention, which the report's "layer 38" figure comes from. Layers 0 and n are refused.
- **Two sites, label and prelabel.** The report says "answer-label token", so `label` is the default; `prelabel`
  is the state that predicts the label, as in Jared's E8. Both are extracted, because extraction is the
  expensive step and fitting is cheap.
- **The defaults follow the report wherever it speaks:**
  - "none" prompts are included (Methods: "used for extraction");
  - H/D >= 4 against H/D <= 1/4, with D the far delay (A.1).

  `--regimes` makes excluding "none" a flag. A within-regime contrast is **not** implemented: it departs from the
  report and awaits a team decision.
- **Reward-contrast control: multiplier >= 25 against <= 5.** The report doesn't define it; this is my reading,
  flagged in the README.
- **Curve:**
  - PCA of the per-horizon means, k = 4 by default (the report's range is 3-8);
  - a Gaussian-kernel local-linear smoother with 0.3-decade bandwidth (grid spacing is 0.185 decade), stored as a
    2001-point polyline; nearest-point projection.

  Local-linear rather than Nadaraya-Watson (a plain weighted average), to avoid inward bias at the grid ends.
  numpy only; no scipy dependency.
- **Curve edit: both readings of the report are implemented, `snap` and `displace`.** The choice is open; see the
  README. The edits are numpy reference implementations. A torch in-model version is deferred to the
  verification work.
- **The replay check records a label margin, not a boolean argmax match.** See the bug-fix section below.
- **`activations/` and `fits/` are git-ignored.** Both regenerate from a baseline run.

## Bugs and corrections found during the session

- **Manifold tests initially failed on my thresholds, not on the code.** Diagnosed before changing anything:
  - The smallest principal cosine between the fitted and true subspace was 0.99691 at noise 0.05, 0.99949 at
    0.02, and 0.99997 at 0.005. That is statistical PCA error, so the 0.999 bound was too tight for the noisiest
    case.
  - The `displace` t-hat shift error was median 0.0278 / 0.0113 / 0.0104 decades at the same three noise levels.
    `snap` stayed at 0.0017.

    Cause: displace keeps the activation's offset from the curve. That offset is normal to the curve at t-hat but
    not at t-hat + Delta wherever the curve turns. It is a property of the mode, not a bug.
  - The tests were rewritten to assert these properties:
    - snap's error is below 0.004 decade;
    - displace's error stays under offset/min speed + 0.004;
    - a separate tighter-noise case expects a principal cosine above 0.9999.
- **The replay check over-reported mismatches.** The first smoke extraction flagged 19/500 replies where the
  replay's argmax at the prelabel site was not the generated label. Inspecting their logits showed every one was
  a tie or a single bf16 step:

  ```
  x0013: generated ' a', replay top2 [' b', ' a'], logit(gen) - logit(top1) = -0.125, top1-top2 0.125
  x0049: generated '2', replay top2 ['2', '1'], logit(gen) - logit(top1) = +0.000, top1-top2 0.000
  matching replays, top1-top2 margin: min 0.000, median 0.250
  ```

  Fix: record `replay_label_margin` (the generated label's logit minus the best other logit) per prompt; a tie
  counts as consistent. extract.json reports the minimum margin, so a real replay failure, which would show a
  large negative margin, can't hide in a count. After the fix: 10 at -0.125, minimum -0.125.
