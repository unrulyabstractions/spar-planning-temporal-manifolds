  layer, with no baseline run and no generation.
- **Files:** `extract_horizon.py` (new); `steer/sites.py` (`locate_horizon`, `horizon_char_span`); `steer/layers.py`

- **Findings while building it:**

  - Prompts without a horizon get a row with empty lists in `horizon_sites.jsonl`, so rows exist for all 700 uids.
- **For the hook:** `at_prompt(indices)` edits chosen prompt tokens per row, adding each row's left padding;

# Later still: the within-regime CAA (branch `within-regime-caa`)

The third of Augusto's requests. PR 17 was merged first; this branch starts from the merged `main`.

## Decisions (Alan)

Options were laid out with prompt counts and a trial on the 2B activations:
- **A.** one direction per regime, long third against short third of the horizon;
- **B.** the regimes' differences pooled into one direction;
- **C.** a regression of activation on log-horizon with regime as a control;
- **D.** A within the model's own choice as well.

**Chosen: A and B, thirds, and `none` left out of the pooled direction.**
- C was rejected for now: it is not a difference of means, so it is a different kind of method from CAA. Worth
  revisiting if the regimes' directions agree on Gemma.
- D was rejected: its cells are too small on this bank (one has 18 prompts, another 11 against 12).
- `none` is out of the pool because the horizon cannot change the answer there; the pool then covers 10 days to 500
  years, the range the choice can test. `caa-none` is still built on its own.

## What was built

- **`steer/fitting.py`:** `within_regime_classes` (per regime, long = t ≥ the 2/3 quantile, short = t ≤ the 1/3
  quantile of its prompts' log-horizon), `pooled_direction` (regime-size-weighted average of the raw mean differences,
  then unit-normalized), `FitSettings.within_quantile` and `.within_pool`, `FitResult.within`, `.within_pooled`,
  `.within_class`, `.direction(key)`, and `direction_keys`. `diagnostics.caa_within` holds class sizes, cut-offs,
  shares of far choices, cosines with caa / choice / reward, and the cosines between regimes.
- **`fit.py`:** `--within-quantile`, `--within-pool`; `directions.npz` gains `caa_none`, `caa_near_only`, `caa_both`,
  `caa_within` and their raw norms; `fit_uids.jsonl` gains `caa_within_class`.
- **`steer/methods.py`, `bundle.py`:** methods `caa-none`, `caa-near_only`, `caa-both`, `caa-within`.
  `bundle.py` now bundles by default every method the fit has, and refuses a requested one the fit lacks. A fit
  written before the two settings existed bundles with their defaults.
- **Behaviour that did not change:** every existing direction and the curve are bit-identical (checked below).

Design notes:
- A regime with fewer than two distinct horizons, or equal quantiles, gets no direction. It is listed under
  `not_formed`, not fitted and not pooled. So smoke-sized fits still run.
- Classes are whole grid horizons, so they are about a third each: 94/97, 43/36, 30/36.
- `refit(horizons=...)` does not recompute regimes (as before). For these methods a label shuffle should stay within
  a regime; this is stated in the hand-over document.

# Evening: seeded sampling and the token cap (branch `seeded-sampling`)

## Decisions (Alan)

- **Seeded sampling** for the decoding question that was blocking the Gemma run.
- **The token cap stays configurable and defaults to 4,096.** It already was configurable
  (`baseline.py --max-new-tokens`), with a default of 8,192.
- **Sampling values:** the model's own generation config, overridable on the command line. Rejected: one fixed set
  for all models (not what Gemma's authors recommend for Gemma), and always-explicit values.
- **When to sample:** when thinking is on. Thinking-off runs stay greedy by default, so the practice hand-over's
  setting still reproduces. Rejected: sampling always, and greedy unless asked.

## What was built

- **`prompt_bank/pbank/local_model.py`:** `Decoding` (greedy, or sample with temperature / top-p / top-k / seed),
  `resolve_decoding`, `model_sampling_defaults`, `add_decoding_args`, `decoding_from_args`;
  `LocalChatModel.generate(..., decoding=GREEDY)`. Every other caller of `generate` is unchanged and still greedy.
- **`prompt_bank/baseline.py`:** `--decoding {auto,greedy,sample}` (default auto), `--temperature`, `--top-p`,
  `--top-k`, `--seed`; `--max-new-tokens` default 4,096. `run.json` records the decoding and where each value came
  from. A greedy run still records the string `"greedy"`, so earlier runs can be resumed with `--decoding greedy`.
- **`steering/extract.py`:** `replay_label_rank` and `replay_consistent` per prompt. For a sampled run the check is
  rank < top_k. `extract.json` records which check applied, `replay_label_not_top` and `replay_max_label_rank`.
- **`steering/tools/check_hook.py`:** the same decoding options (default greedy).
- **`steering/steer/methods.py`:** bundles record `fitted_on.decoding`.
- **`steering/tools/vast_smoke.sh`:** its label audit uses `replay_consistent`.

Design decisions:
- **Seeding per batch, from (run seed, the batch's prompts).** A batch then repeats exactly whatever was generated
  before it, a resumed run matches an uninterrupted one, and the hook gate's unhooked and hooked runs draw the same
  numbers with no extra plumbing. Rejected: seeding once per run (a resume would diverge), and a per-prompt seed
  (transformers samples a whole batch from one generator, so it would need batch 1).
- **Nothing is read from the model's generation config implicitly.** The three values are always passed to
  `generate()`, and a value found neither on the command line nor in the model's config is an error.
- **The sampled replay check is weaker than the greedy one,** and says so: it tests top-k membership only, not
  top-p, and cannot tell which allowed token was drawn.

# Night: preparing the Gemma smoke run (branch `gemma-smoke-prep`)

Two fixes agreed with Alan before renting a GPU. The run itself is not started.

## 1. Outputs name their code commit on a machine without `.git`

- **Problem** (2026-11-15, gotcha 6): code copied by an rsync that skips dotfiles has no `.git`, so every output
  recorded `"unknown"`.
- **Fix:** `python -m pbank.provenance stamp` writes `CODE_STAMP.json` at the repository root (git-ignored): the commit
  and the SHA-256 of every tracked file. Without git, `git_commit` returns the stamped commit if the files of the
  directories it is asked about still match, the commit plus `-modified` if any differs or is missing, and
  `"unknown"` with no stamp. With git, the stamp is ignored.

  are now left out of the stamp, and the test copies without dotfiles as the real copy does.
