## The prompt

The prior project's structured format (SITUATION / TASK / OBJECTIVE /
CONSTRAINT / ACTION / FORMAT), generated by Alan's generator
(`spar_horizon/full_bank.py`, `horizons.py`, copied from `../alan/`): pick a
small near payout or a large far payout "for this time horizon: X", X one of
48 log-spaced horizons from 30 seconds to 500 years in natural units (84
minutes, 43 hours, 15 months). Delays, rewards and option order are drawn per
prompt; about 1 in 18 prompts has no horizon. Records carry `near_label`,
`regime` (`none` / `near` / `both` / `null`) and `truth` (the rational choice
where one is defined). The FORMAT line asks for `I choose: <a) or b)>`; the
model writes it after reasoning and `model_io.locate_label` finds the label
after it, as Alan's parser does.

## Kept positions (thinking on)

```
[ suffix:    <|im_end|> \n <|im_start|> assistant \n ]              region suffix
[ think:     think@0.25  think@0.5  think@1 ]                       region think
[ pre:       </think>  \n\n ]                                       region pre
[ ... I choose (the model's own lead, variable length, not kept) ]
[ pre-label: ':' ]                                                  region prelabel
[ answer:    a  )  ... (6 tokens) ]                                 region answer
```

The "suffix newline" probed in `06` is the `\n` after `<|im_end|>`.

Think positions sit at fractions of each prompt's own think span; think@1
is the last token the model wrote in the block. On a natural close that is
the `.\n` right before `</think>`; on a forced close it is wherever the cut
fell, often mid-sentence, and `</think>` follows an appended `\n`. So think@1
means different things in the two groups: split by `forced_mask` when
reading it. Regions are stored in `activations.npz`
and the manifest.

## Reasoning on the 8B

The 8B reasons for about 1.7k tokens on the full bank (median) and loops on
some horizons, mostly long ones, so the think block is force-closed at
`max_think_tokens` (3,072). Forced prompts are kept and flagged
(`forced_mask`); 103 of 500 on the full bank. Generation is batched (default
12 on the 4090, steps down on out-of-memory) and every prompt's greedy
generation is cached in `<results>/gen_cache/`, keyed by settings and input
ids, so reruns after an analysis change skip generation (`--no-cache`
disables). E8 feeds the cached reasoning back without generating.

## Shipping

Rent the box in the vast.ai console, then from `spar-planning-temporal-manifolds/`
(`just` lists the verbs):

```
just new ssh -p 41234 root@ssh5.vast.ai -L 8080:localhost:8080   # the console's ssh line, pasted
just push                                                        # ships this project, not out/, then installs requirements.txt
just sync      # results into SPAR/results/
just stop      # or: just down
```

`just new` stores the host and port and matches them to an instance on the
vast.ai account, so `status`, `stop` and `down` work too. After `just resume`
the port can change; paste the new line with `just new`. Generation tests are
skipped on the box: bf16 batched greedy is not token-identical to
single-prompt, so they are CPU tests (`local_checks.py`).
